# BehaviorLens 📋

**A behavior-tracking web app for after-school staff: log incidents in seconds, then see the patterns behind them.**

> Built by [Crystal Patino](https://github.com/crystalpatinoDEV) · Psychology @ Hunter College

---

## Why I built this

At New York Edge, I tracked student behaviors by hand: paper sheets, clipboards, and notes scribbled between activities. The information was valuable, but it was nearly impossible to *use*. Nobody had time to flip back through weeks of paper to ask questions like:

- Do meltdowns spike on Mondays, or after long weekends?
- Is one activity (transitions, homework time, gym) a consistent trigger?
- Is a particular student improving since we changed their routine?

BehaviorLens turns that clipboard into a fast logging form and a dashboard, so staff can spot patterns and respond earlier instead of reacting after the fact.

The logging model is based on the **ABC framework** from applied behavior analysis: **A**ntecedent (what happened right before), **B**ehavior (what the student did), **C**onsequence (how staff responded). This is the same structure used by school psychologists and behavior specialists, so the data is meaningful and not just a list of complaints.

## Features

### MVP
- **Quick-log form:** record an incident in under 30 seconds (student, date/time, activity, antecedent, behavior type, intensity 1–5, staff response, notes)
- **Student roster:** add, edit, and archive students
- **Incident history:** filterable list by student, date range, activity, or behavior type
- **Pattern dashboard:**
  - Incidents by day of week (bar chart)
  - Incidents by activity (bar chart)
  - Incidents over time, per student or program-wide (line chart)
  - Most common antecedents (ranked list)

### Stretch goals
- Staff login with roles (staff can log; site directors can view all reports)
- Positive behavior logging (track wins, not only problems)
- Export a student summary as a PDF for parent or counselor meetings
- Time-of-day heatmap
- Mobile-friendly layout for logging on a phone during program hours

## Tech stack

| Layer | Tool | Why |
|---|---|---|
| Frontend | React + Vite | Most in-demand frontend library; fast dev setup |
| Charts | Chart.js (via react-chartjs-2) | Simple, well-documented charts |
| Backend | Node.js + Express | REST API in the same language as the frontend |
| Database | PostgreSQL | Industry-standard relational database |
| ORM | Prisma | Readable schema, easy migrations |
| Deployment | Render or Railway (API + DB), Vercel (frontend) | Free tiers, live demo link for the resume |

## Data model

```
Student
  id, firstName, lastInitial, grade, active, createdAt

Activity
  id, name  (e.g., Homework, Gym, Snack, Arts, Transition, Dismissal)

Incident
  id, studentId → Student, activityId → Activity,
  occurredAt (date + time),
  antecedent      (e.g., "told to stop game", "peer conflict", "schedule change")
  behaviorType    (e.g., meltdown, aggression, elopement, refusal, disruption)
  intensity       (1–5)
  durationMinutes
  staffResponse   (e.g., redirection, break space, called parent)
  notes, loggedBy, createdAt
```

## API endpoints

| Method | Route | Purpose |
|---|---|---|
| GET | `/api/students` | List students |
| POST | `/api/students` | Add a student |
| PATCH | `/api/students/:id` | Edit or archive a student |
| GET | `/api/incidents?studentId=&from=&to=&activityId=` | Filtered incident list |
| POST | `/api/incidents` | Log an incident |
| GET | `/api/stats/by-weekday` | Counts grouped by day of week |
| GET | `/api/stats/by-activity` | Counts grouped by activity |
| GET | `/api/stats/over-time?studentId=` | Weekly counts over time |

## Privacy and ethics

Student behavior data is sensitive. This project is designed with that in mind:

- **All data in this repo and the live demo is fake.** It's generated by a seed script; no real students from any program are included.
- Students are stored by first name and last initial only.
- A real deployment would need to follow FERPA and the program's data policies, use authenticated access, and limit who can view individual student records.

## Getting started

```bash
# 1. Clone the repo
git clone https://github.com/crystalpatinoDEV/behaviorlens.git
cd behaviorlens

# 2. Install dependencies
cd server && npm install
cd ../client && npm install

# 3. Set up the database
#    Create a .env file in /server with:
#    DATABASE_URL="postgresql://USER:PASSWORD@localhost:5432/behaviorlens"
cd ../server
npx prisma migrate dev
npm run seed        # loads ~300 fake incidents across 15 students

# 4. Run it
npm run dev                       # API on http://localhost:3001
cd ../client && npm run dev       # App on http://localhost:5173
```
